# 냉동고 시뮬레이터

실제 냉동고 대신 온도 변화와 문 상태를 재현하는 프로그램입니다.

시뮬레이터 프로세스 1개가 냉동고 1대를 담당합니다. 동일한 코드를 서로 다른 장비 설정으로 실행하면 여러 냉동고를 구성할 수 있습니다.

<br />

## 구조

```text
freezer_simulator.py    온도 시뮬레이션 및 웹 화면
simulator_mqtt.py       MQTT 통신 및 상태 저장
__init__.py             Python 패키지 구성
```

공통 모듈은 `common/`, 냉동고 이미지는 최상위 `image/`를 사용합니다.

<br />

## 주요 기능

- 문 열림 / 닫힘에 따른 온도 변화
- 현재 온도 / 설정 온도 / 문 상태 / 냉각 상태 표시
- 온도 및 경보 조건에 따른 화면 색상 변경
- 로그 조회 및 검색
- MQTT 측정값 전송
- 승인된 설정 온도 명령 적용 및 결과 응답
- 현장 웹에서 요청한 문 열기 / 닫기 처리
- 순번 및 재전송 정보를 상태 파일에 저장

<br />

## 실행

설치와 공통 설정 방법은 [최상위 README](../README.md)를 참고합니다.

프로젝트 최상위에서 실행합니다.

```powershell
python -m simulator.freezer_simulator
```

기본 웹 포트는 `5000`입니다.

같은 PC에서 확인할 때는 다음 주소로 접속합니다.

```text
http://127.0.0.1:5000
```

다른 PC에서는 시뮬레이터가 실행 중인 PC의 주소를 사용해야 하며, 네트워크 및 방화벽에서 접근이 허용되어 있어야 합니다.

<br />

## 환경변수

| 이름 | 필수 | 설명 |
| --- | --- | --- |
| `SITE` | 필수 | 시설 ID / 예: `site01` |
| `DEVICE` | 필수 | 냉동고 ID / 예: `fz01` / 기본 MQTT 계정 이름으로도 사용 |
| `SIM_MQTT` | 선택 | MQTT 사용 여부 / 기본값 `false` / 연동 시 `true` |
| `MQTT_HOST` | MQTT 사용 시 | MQTT 브로커 주소 |
| `MQTT_PORT` | MQTT 사용 시 | MQTT TLS 포트 / 기본값 `8883` |
| `MQTT_CA` | MQTT 사용 시 | CA 인증서 파일 경로 |
| `MQTT_USER` | 선택 | 단독 실행용 MQTT 계정 / 기본값은 `DEVICE` / 장비 ID와 일치해야 함 |
| `MQTT_PASS` | MQTT 사용 시 택일 | 단독 실행용 비밀번호 / `SIM_PASSWORD`보다 우선 |
| `SIM_PASSWORD` | MQTT 사용 시 택일 | 해당 장비의 비밀번호 / 통합 실행에서는 이 이름 사용 |
| `MQTT_CLIENT_ID` | 선택 | 단독 실행용 클라이언트 ID / 기본값 `sim-<SITE>-<DEVICE>` |
| `WEB_HOST` | 필수 | 웹 수신 주소 / 기본값 `0.0.0.0` |
| `SIM_WEB_PORT` | 필수 | 웹 포트 / 기본값 `5000` |
| `WEB_PORT` | 선택 | 단독 실행에서 `SIM_WEB_PORT`를 덮어쓸 포트 |
| `STATE_DIR` | MQTT 사용 시 | 순번 및 재전송 정보 저장 폴더 / 기본값 `state/` |
| `SIM_DB` | 선택 | 상태 DB 전체 경로 / 지정하면 자동 생성 경로보다 우선 |

시뮬레이터의 기본 MQTT 계정 이름은 `DEVICE`입니다. 예를 들어 `fz01` 장비는 해당 장비에 발급된 계정과 비밀번호를 사용합니다.

단독 실행에서는 `MQTT_USER`, `MQTT_PASS`, `MQTT_CLIENT_ID`, `WEB_PORT`도 사용할 수 있습니다. 시뮬레이터의 MQTT 계정은 장비 ID와 일치해야 합니다.

같은 PC에서 여러 시뮬레이터를 실행하면 장비 ID / 웹 포트 / 클라이언트 ID / 상태 파일을 구분합니다. 재시작 시에는 해당 장비의 기존 상태 파일을 유지합니다.

환경변수 예시는 [simulator.env.example](../config/simulator.env.example)을 참고합니다.

## MQTT 통신

기본 토픽 구조는 다음과 같습니다.

```text
coldguard/<시설 ID>/<장비 ID>/<종류>
```

| 종류 | 방향 | 역할 |
| --- | --- | --- |
| `telemetry` | 시뮬레이터 -> 브로커 | 온도 / 설정 온도 / 문 상태 / 냉각 상태 전송 |
| `apply` | 제어기 -> 시뮬레이터 | 검증을 통과한 설정 명령 수신 |
| `applied` | 시뮬레이터 -> 제어기 | 실제 설정 적용 결과 전송 |
| `door` | 현장 웹 -> 시뮬레이터 | 문 열기 / 닫기 요청 수신 |

측정값은 1초 주기로 전송하며, QoS 1 / retain false를 사용합니다.

측정값의 `seq`는 장비별 순번입니다. 재전송할 때는 기존 순번을 유지합니다.

<br />

## 여러 냉동고 운영

장비별로 다음 값을 구분합니다.

- 시설 ID / 장비 ID
- MQTT 계정 및 비밀번호
- MQTT 클라이언트 ID
- 상태 저장 파일
- 같은 PC에서 실행하는 경우 웹 포트

같은 냉동고를 재시작할 때는 기존 상태 파일을 유지합니다. 서로 다른 냉동고가 같은 상태 파일을 사용하면 안 됩니다.

<br />

## 연동 확인

- TLS 연결 및 MQTT 계정 인증 성공 확인
- `apply` / `door` 구독 권한 확인
- `telemetry` 측정값 수신 확인
- 문 조작 후 `door_open` 변경 확인
- 승인 명령 적용 후 `applied` 전송 확인
- 재시작 후 순번 유지 및 재전송 확인
